# Reify

> Turn one sentence into a website, resume, mini-game, travel guide, image set, video, or code demo — and deploy it as a reachable page.

[简体中文](README.md) | **English**

Reify is a generative design agent: describe what you want in one sentence, and the agent plans, generates, validates, builds, and publishes it while streaming progress over SSE. Common requests use built-in templates; long-tail requests are generated by an OpenAI-compatible model, self-checked, and fall back to templates on failure.

- Capabilities: websites, resumes, mini-games, travel guides, images, videos, and code demos
- Automatic stack selection: static HTML / Vite React / Next.js, with build details hidden from users
- Multi-user accounts, project isolation, live progress, refine, sharing, and export
- Templates plus model generation, with generated content built and run in isolated sandboxes

## Architecture

![Reify architecture](docs/diagrams/reify-architecture.svg)

Reify is organized into six layers:

| Layer | Components | Responsibility |
|---|---|---|
| Interaction | React + Vite workspace | Compose prompts, browse templates, follow plans/diffs/events, manage projects |
| Access and control | Caddy, FastAPI, auth, quotas | TLS/reverse proxy, sessions, project APIs, SSE, sharing, and audit |
| Orchestration and generation | Built-in templates, routing, OpenAI-compatible models | Break down requests, choose templates or general generation, run structural and offline checks |
| Build | OpenSandbox build sandboxes | Install dependencies and build React/Next sources, validate and return artifacts |
| Runtime and delivery | Project runtimes, Next SSR runtime | Serve static/React projects at `/p/` and `/s/`, Next projects at `/apps/` |
| Data | SQLite, project workspaces, runtime records | Users, sessions, project metadata, events, artifacts, and runtime state |

## Quick start

Prerequisites:

- Python 3.12+ (verified up to 3.14)
- Node.js 20+ (24 recommended) and npm
- Optional: Docker + OpenSandbox, only needed for React/Next source builds
- Optional: an OpenAI-compatible model endpoint; without one, deterministic templates are used

```bash
# 1. Build the frontend into web/dist
cd frontend
npm ci
npm run build
cd ..

# 2. Create the Python environment
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt

# 3. Start the server
REIFY_ADMIN_PASSWORD=your-password \
.venv/bin/python -m uvicorn server.main:app --host 127.0.0.1 --port 7801
```

Open <http://127.0.0.1:7801>. The admin username defaults to `admin`; if no password is set, the startup log prints a random one.

`./run.sh` creates the venv, installs dependencies, and listens on `0.0.0.0:12888`, but does not build the frontend; run step 1 first.

### Frontend dev mode

```bash
cd frontend
npm run dev
# http://127.0.0.1:5173
# if the backend is not on 7801:
REIFY_BACKEND=http://127.0.0.1:12888 npm run dev
```

### Enable the source build sandbox (optional)

React/Next sources need Docker and an OpenSandbox Server:

```bash
uvx opensandbox-server init-config ~/.sandbox.toml --example docker
uvx opensandbox-server --config ~/.sandbox.toml

REIFY_SANDBOX=opensandbox \
REIFY_SANDBOX_DOMAIN=127.0.0.1:8080 \
REIFY_SANDBOX_API_KEY=your-sandbox-key \
REIFY_SANDBOX_BUILD_MEMORY=4Gi \
REIFY_SSR_PREVIEW=1 \
.venv/bin/python -m uvicorn server.main:app --host 127.0.0.1 --port 7801
```

Without the sandbox, React/Next requests fall back to static templates; other capabilities are unaffected.

## Build the image

```bash
docker build -t reify-app:latest -f Dockerfile.app .
```

Two stages: Node builds `frontend/`, then `web/dist` is copied into a `python:3.12-slim` runtime image.

## Tests

```bash
# Test dependencies
.venv/bin/pip install -r requirements-dev.txt

# Backend unit tests
.venv/bin/python -m pytest -q

# Frontend unit tests, typecheck, build
cd frontend && npm test && npm run typecheck && npm run build && cd ..

# Real TypeScript builds for generated projects (npm ci + tsc + vite/next build)
.venv/bin/python tests/e2e_typescript_scaffolds.py

# Full UI flow (real uvicorn + Chrome + mock LLM, no sandbox)
.venv/bin/python tests/e2e_browser.py
```

Browser E2E uses system Google Chrome. Sandbox-related cases need a working OpenSandbox:

```bash
.venv/bin/python tests/e2e_react_sandbox.py
.venv/bin/python tests/e2e_next_ssr.py
.venv/bin/python tests/e2e_refine.py
```

Regression tests against a deployed instance take `REIFY_E2E_BASE`; `*_live.py` calls a real model and consumes tokens:

```bash
REIFY_E2E_BASE=https://your-host:12888 .venv/bin/python tests/e2e_deployed.py
REIFY_E2E_BASE=https://your-host:12888 .venv/bin/python tests/e2e_next_live.py
REIFY_E2E_BASE=https://your-host:12888 .venv/bin/python tests/e2e_game_live.py
REIFY_E2E_BASE=https://your-host:12888 .venv/bin/python tests/e2e_longtail_live.py
```

## Key environment variables

| Variable | Default | Purpose |
|---|---|---|
| `REIFY_HOST` / `REIFY_PORT` | `0.0.0.0` / `12888` | Listen address and port |
| `REIFY_DATA` | `./data` | SQLite and user workspace root |
| `REIFY_DB` | `data/reify.db` | SQLite path |
| `REIFY_ADMIN_USER` / `REIFY_ADMIN_PASSWORD` | `admin` / random | First admin; a random password is generated when empty |
| `REIFY_REGISTRATION` | `open` | `open` or `closed` |
| `REIFY_COOKIE_SECURE` | `0` | Must be `1` for HTTPS deployments |
| `REIFY_LLM_ENABLED` | `1` | Enable the model; only effective when BASE_URL is set |
| `REIFY_LLM_BASE_URL` / `REIFY_LLM_API_KEY` / `REIFY_LLM_MODEL` | empty | OpenAI-compatible endpoint |
| `REIFY_LLM_LONGTAIL_MAX_TOKENS` | `24000` | Long-tail output budget |
| `REIFY_MEDIA_API_BASE` / `REIFY_MEDIA_API_KEY` | inherits LLM | Image/video API |
| `REIFY_SANDBOX` | `off` | `opensandbox` enables source builds |
| `REIFY_SANDBOX_DOMAIN` | `127.0.0.1:8080` | Sandbox Server address |
| `REIFY_SANDBOX_API_KEY` | empty | Sandbox API key |
| `REIFY_SANDBOX_BUILD_MEMORY` | `2Gi` | Build sandbox memory; `4Gi` recommended for Next |
| `REIFY_SANDBOX_CONCURRENCY` | `2` | Concurrent builds |
| `REIFY_NPM_REGISTRY` | `https://registry.npmmirror.com` | npm registry for builds |
| `REIFY_SSR_PREVIEW` | `0` | Enable `/apps/*` preview |
| `REIFY_SSR_PORT` | `12889` | SSR origin port |
| `REIFY_RUNTIME_IDLE` / `REIFY_RUNTIME_TTL` | `600` / `3600` | Runtime idle stop / max lifetime (seconds) |
| `REIFY_MAX_PROJECTS_PER_USER` | `50` | Projects per user |
| `REIFY_MAX_ACTIVE_PER_USER` | `2` | Concurrent tasks per user |
| `REIFY_MAX_STORAGE_PER_USER` | `1073741824` | Storage per user (1 GB) |

See [.env.example](.env.example) for the full list.

### Environment files (not committed)

Sensitive settings are injected through env files. `.gitignore` excludes `.env`, `.env.*`, `.auth.env`, `.sandbox.env`, `.llm.env`, and `.runtime.env`, keeping only `.env.example`, so none of these files exist in the remote repository.

| File | Main variables | Purpose |
|---|---|---|
| `.env` | Any `REIFY_*` needed locally | Copy from `.env.example`; the app does not load it automatically, so use `set -a; source .env; set +a` before starting |
| `.auth.env` | `REIFY_ADMIN_USER` / `REIFY_ADMIN_PASSWORD` (legacy: `REIFY_PASSWORD`), `REIFY_COOKIE_SECURE`, `REIFY_REGISTRATION` | Created by the deploy script on first run; holds the initial admin password |
| `.sandbox.env` | `REIFY_SANDBOX`, `REIFY_SANDBOX_DOMAIN`, `REIFY_SANDBOX_API_KEY`, `REIFY_SANDBOX_BUILD_MEMORY`, `REIFY_SANDBOX_EGRESS`, `REIFY_PROJECTS`, `REIFY_SSR_PREVIEW`, `REIFY_SSR_PORT`, `REIFY_NPM_*` | Generated/updated by the deploy script; rebuild containers or the sandbox after changes |
| `.llm.env` | `REIFY_LLM_ENABLED`, `REIFY_LLM_BASE_URL`, `REIFY_LLM_MODEL`, `REIFY_LLM_API_KEY`, optional `REIFY_LLM_TIMEOUT` / `REIFY_LLM_MAX_TOKENS` and media variables | Create manually with mode 600; never commit or paste into chat |
| `.runtime.env` | Merge of `.auth.env` + `.llm.env` + `.sandbox.env` | Generated by the deploy script, mode 600, injected via `docker --env-file`; the container reads this file |

The deployment directory is `/data/reify-deploy`. The script regenerates `.runtime.env` on every run; after changing `.auth.env`, `.sandbox.env`, or `.llm.env`, rerun `./deploy_remote.sh root@your-host 12888` to apply it.

## Resources and ports

### Ports

| Port | Purpose | Exposure |
|---|---|---|
| 80/tcp | ACME HTTP-01 and redirect | Public |
| 12888/tcp | Platform UI/API/SSE, `/p/`, `/s/` | Public |
| 12889/tcp | Next SSR `/apps/*` separate origin | Public (when Next is enabled) |
| 8080/tcp | OpenSandbox Server | Container network only |

### Resource budget

| Scenario | vCPU | RAM | Disk |
|---|---:|---:|---:|
| Static templates/general generation only | 2 | 2 GB | 10 GB |
| Full capability (React/Next builds + 1-2 SSR runtimes) | 4-8 | 16 GB | 60 GB |
| Minimum for Next | 4 | 8 GB | 30 GB |

Service limits:

- Platform container: 2 vCPU / 4 GiB / 512 PIDs, `cap-drop ALL`
- Source build sandbox: 1 vCPU / 2-4 GiB, concurrency 2
- Next runtime: 1 vCPU / 1 GiB, 1-hour TTL, stopped after 10 idle minutes
- Idle memory about 250 MiB (platform + Caddy + Sandbox Server); images about 370 MB total
- Default storage quota 1 GB per user

## Deployment

The deployment environment needs Docker Engine and inbound access to `80`, `12888`, and `12889`:

```bash
./deploy_remote.sh root@your-host 12888
```

The script syncs the source to `/data/reify-deploy`, builds the `reify-app` image, and starts the platform, Caddy, and OpenSandbox containers with that directory mounted at `/app`. Keep secrets in `.auth.env`, `.sandbox.env`, and `.llm.env` (never commit them); the script merges them into a 600-mode `.runtime.env` injected into the container.
